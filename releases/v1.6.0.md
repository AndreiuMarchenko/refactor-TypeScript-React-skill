# v1.6.0 — Whole-folder architecture and dependency boundaries

This release strengthens the review of the resulting architecture: agents must assess the full authorized inventory, justify retained abstractions, and distinguish cohesive ownership from unnecessary file fragmentation.

## Changes

- Establish whole-folder responsibility, state/resource/contract ownership, dependency direction, and end-to-end data/effect flow before detailed helper edits. Read prior reports initially for scope and operational constraints, then reconcile their architectural conclusions against current code.
- Finish with a consolidation review of retained originals, destinations, tiny modules, placement, navigation, and representative change scenarios. Closing inherited findings or enumerating declarations does not establish a coherent final layout.
- Make module granularity explicit: an independent rule or reusable invariant does not automatically need its own file. Shared validation may live in an existing cohesive owner while preserving distinct acceptance and field-presence contracts. A new module must improve responsibility boundaries or navigation.
- Require evidence-backed dispositions for private policy helpers, exported declarations, aliases, bound exports, and re-exports, including unchanged candidate files. Existing callers, a facade label, or a passing import scan alone cannot justify retention.
- Evaluate re-export paths against direct owner imports. Preserve evidenced public/build/encapsulation boundaries; migrate consumers and remove relays without such a responsibility.
- Add a role-based dependency matrix for domain rules, application scenarios, external adapters, and composition. Business logic stays independent of concrete persistence, ORM/network clients, React, global stores, and browser APIs; consumer-owned ports connect external implementations.
- Review transitive helpers and type/data dependencies for external representation leaks. Framework-owned UI and adapters may legitimately depend on their framework. Do not manufacture layers, repositories, duplicate DTOs, or containers where the actual boundary does not require them.
- Integrate whole-folder layout, layer roles, and residual symbol decisions into the existing report template and mixed-mapper grading rubric. Reports preserve evidence; their length or number of completed tables does not prove architectural quality.
- Update skill metadata and release documentation to `1.6.0`.

## Validation and limits

- React demo: 18 After behavior checks, verification of the six expected Before regressions, TypeScript checking, and production build.
- Mixed-mapper fixture: 18 behavior checks and TypeScript checking.
- Skill metadata, local Markdown links/anchors, runtime resources, and release package contents checked before publication. GitHub Actions runs both example checks for the release commit.

This is a guidance update, not a controlled reliability benchmark or a measured time/token optimization. The existing independent evaluation record applies to its recorded snapshot; changes to the rubric are not new evaluation results. Behavior checks and complete inventories do not replace review of actual ownership, effects, dependency direction, and layout. No universal file count, mandatory class conversion, or one-function-per-file rule is introduced.
