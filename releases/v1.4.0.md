# v1.4.0 — Structural closure, ownership, and helper cleanup

This release makes architectural completion depend on closing concrete responsibility findings and adds explicit review of object ownership, helpers, and public entry points.

## Changes

- Each mixed file needs a responsibility map with logical groups, inputs, outputs, dependencies, effects, and independent reasons to change. Broad labels such as mapper or projection do not establish cohesion.
- Every identified in-scope mixing finding needs an implemented separation and caller migration. Minimal structure is assessed only among designs that close those findings; moving a mixed body does not complete the work.
- Review follows transitive helper calls for cache writes and other effects. Required mutations retain an explicit owner, ordering, and failure semantics.
- Reports and templates distinguish behavioral verification from architectural verification. Green tests cannot close an unresolved structural finding.
- Class/value-object versus function/DTO decisions require ownership and invariant evidence. Helper decisions explicitly retain, consolidate, relocate, or remove the affected abstraction, with caller migration where needed.
- Re-export-only public APIs are assessed separately from redundant relays. Utility filenames and facade comments cannot substitute for consumer and boundary evidence.
- Related construction, parsing, and serialization paths must have an explicit validity policy, semantic round-trip checks, and documented handling of invalid and precision-sensitive inputs. TypeScript module documentation is added to the source catalog.
- A reproducible mixed-mapper project, maintainer grading rubric, and independent evaluation record complement the existing React lifecycle demo. CI now runs both example projects.
- Skill metadata and README identify version `1.4.0`.

## Validation and limits

Both executable examples were checked for this release: the React demo passes 18 After tests, expected-failure baseline verification, type-checking, and production build; the original mixed-mapper fixture passes 18 behavior checks and type-checking. Its architecture deliberately remains mixed as input for future evaluations. Skill metadata, Markdown targets/anchors, and copied installation resources were validated.

A recorded independent run on a strengthening snapshot separated the mapper's policies, made cache effects explicit, and removed three old implementation files. Maintainer replay confirmed 18 unchanged tests, 161,280 output/cache comparisons, and six ordered-effect scenarios. The source and skill fingerprints, review findings, retained local evidence, and limitations are documented in the [evaluation record](https://github.com/AndreiuMarchenko/refactor-TypeScript-React-skill/blob/v1.4.0/examples/mixed-mapper/evaluation.md).

That single run does not establish reliability across projects. Later object/function, helper-disposition, public-relay, and construction/parsing criteria were not independently forward-tested in that run. CI checks fixture behavior and types; architectural grading remains separate. No production migration or runtime speedup is claimed.
