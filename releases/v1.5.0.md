# v1.5.0 — Continuous execution and recoverable context

This release adds a project-neutral execution workflow for completing an authorized refactoring scope without repeatedly restarting analysis or regenerating unchanged verification evidence.

## Changes

- One declared inventory, baseline, migration ID, and finding ledger guide implementation through caller migration, cleanup, residual review, and required verification. Internal edits are not separate tasks that require another prompt to continue.
- A concise Execution Checkpoint in the existing module report preserves source state, accepted decisions, open findings, changed paths, verification applicability, and the next action. Resumption compares current inputs with that checkpoint and continues from the delta.
- Extraction is followed by review of both remaining original files and all destinations. Completion requires closure of the mapped findings, rather than only cleaner extracted modules.
- Verification receipts record coverage, relevant input state, execution conditions, and actual results. Targeted checks support iteration; combined required checks support closure. Successful results may be reused only with evidence of unchanged inputs and assumptions, retaining their original timestamps.
- Reporting-only edits do not automatically invalidate runtime/build results when reports are not inputs. Relevant source, configuration, dependency, generated-input, or environment changes invalidate affected receipts; uncertainty or unresolved failures requires verification.
- Local completion is distinguished from unrelated outstanding work in a broader migration. Scope cannot be silently expanded or narrowed to alter the endpoint.
- Domain-specific wording in runtime rules is replaced with general ownership criteria, integration commands use neutral path placeholders, and generated documentation follows the user's language instruction or project conventions. The workflow assumes no particular application, business domain, or test runner.
- Skill metadata and README identify version `1.5.0`.

## Validation and limits

Skill metadata, Markdown links and anchors, report-template integration, and copied installation resources are checked. Both existing repository examples are covered by the release commit's CI checks.

This is an execution-policy update. It does not establish measured time/token savings, guarantee that an agent will never lose context, or claim a new independent agent benchmark. Required behavior and architectural closure checks remain in force.

## Install or update

Follow the [installation instructions](https://github.com/AndreiuMarchenko/refactor-TypeScript-React-skill/blob/v1.5.0/README.md#installation). Refresh `SKILL.md`, `LICENSE`, `agents`, `references`, and `assets` together so the new execution reference and checkpoint templates are available.
