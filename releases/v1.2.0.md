# v1.2.0 — Decision-driven sources and engineering records

This release connects source selection to concrete refactoring problems and makes significant decisions reviewable through a shared Engineering Decision format.

## Changes

- Seven additional official sources cover React state identity, state structure, reducers, external store subscriptions, Testing Library's guiding principles, Playwright best practices, and typescript-eslint's `no-unsafe-assignment` rule. Each entry identifies when to read it and the decision or verification it supports.
- Sources are selected for the observed problem; documentation does not by itself justify adding a pattern or dependency. Existing implementations and simpler alternatives must be evaluated against their actual responsibilities and behavior.
- Significant decisions use Problem, Evidence, Source, Decision, Alternatives, Cleanup, and Verification fields. Evidence, decision, cleanup, and verification are explicit, with proposed work distinguished from executed changes and checks.
- The module migration report template and reporting workflow use the same decision format and link cleanup IDs and verification records instead of duplicating evidence.
- Contract reuse requires comparing values, ownership, invariants, consumers, and evolution rationale. Shared concepts use a common contract or justified specialization; matching fields alone do not justify merging types, and aliases need a distinct purpose. Final review records removed duplicates, reasons for retained separate contracts, and intentional optional/null/undefined distinctions.
- Builder and Template Method references are conditional comparisons with simpler construction or composition, rather than default architectural choices.
- Skill metadata and README now identify version `1.2.0`.

## Validation

All seven newly added official documentation pages were checked when updating the source catalog. Skill metadata, local Markdown targets and anchors, packaged resources, and the copied installation layout were validated for this release.

The existing React demo passes all 18 After checks. Baseline verification reproduces exactly six expected Before regressions while six preserved behavior checks pass. Type-checking and the production build pass. These checks cover the demo scenario; they do not establish independent agent evaluation of source selection, contract-reuse decisions, or the decision-reporting workflow.

## Install or update

Follow the [installation instructions](https://github.com/AndreiuMarchenko/refactor-TypeScript-React-skill/blob/v1.2.0/README.md#installation). Refresh `SKILL.md`, `LICENSE`, `agents`, `references`, and `assets` together so the source catalog, reporting guidance, and templates remain consistent.
